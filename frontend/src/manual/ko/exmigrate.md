# ExMigrate

고객사 엑셀 파일의 구조와 수식을 분석해 ERD(테이블 설계) 초안을 만들고, 확정한 ERD로 DB 생성 스크립트(DDL)와 데이터 적재 스크립트를 만드는 도구입니다. 왼쪽 메뉴 **분석 › ExMigrate 엑셀 분석**에서 엽니다.

- 매크로가 든 `.xlsm` 파일도 읽을 수 있지만 매크로는 **실행하지 않습니다**.
- FDE Toolbox가 외부 DB에 직접 데이터를 넣지 않습니다. 만든 스크립트를 내려받아 고객사 환경에서 실행합니다.
- 업로드한 파일과 분석 결과는 고객사별로 분리되어 저장되고, 업로드·확정·내보내기는 감사 로그에 남습니다.

## 엑셀 업로드

1. 위쪽에서 고객사를 고르고, 화면에서 **인게이지먼트**를 고릅니다.
2. 엑셀 파일(`.xlsx`, `.xlsm`)을 고르고 **업로드·분석**을 누릅니다.
3. 분석이 끝나면 상세 화면이 열립니다. 목록에서는 파일명, 시트 수, 수식 수, ERD 상태(초안/확정됨)를 볼 수 있습니다.

## 구조 분석

시트마다 범위, 추정한 헤더 행, 데이터 행 수, 열별 정보를 보여줍니다.

| 항목 | 뜻 |
| --- | --- |
| 타입 | 값으로 추정한 타입(정수, 소수, 참/거짓, 날짜, 날짜시간, 텍스트) |
| 빈 값 % | 데이터 행 중 비어 있는 비율 |
| 고유값 | 서로 다른 값의 개수 |
| 수식 셀 | 그 열에서 수식이 들어 있는 셀 수 |
| 예시 | 값 예시 최대 3개 |

**품질 경고**에는 병합 셀, 데이터 중간의 빈 행, 헤더가 빈 열, 중복 헤더, 타입이 섞인 열, 빈 시트, 외부 통합문서 참조가 표시됩니다. 이관 전에 원본을 정리할 곳을 찾는 데 씁니다.

## 수식 분석

- 1단계: 수식이 있는 셀의 위치와 개수(시트마다 처음 50개 셀을 보여줍니다).
- 2단계: SUM, IF, VLOOKUP, INDEX/MATCH 같은 단순 함수의 사용 빈도와, 다른 시트를 참조하는 수식의 개수.
- LAMBDA, LET 같은 복잡한 수식은 개수만 세고 해석하지 않습니다.

## ERD 편집과 확정

**ERD** 탭에서 시트마다 테이블 후보가 하나씩 만들어집니다. 열 이름은 DB에 쓸 수 있는 이름으로 바뀌고, 원래 이름은 "원래 이름"에 남습니다. 빈 값이 없고 값이 모두 다른 `id`, `코드`, `번호` 같은 열은 PK 후보로 표시됩니다. VLOOKUP·XLOOKUP·MATCH로 다른 시트를 찾는 수식이 있으면 관계(자식 열 → 부모 열) 후보가 만들어집니다.

1. 테이블 이름, 열 이름, 타입, PK, NULL 허용을 고칩니다. 필요 없는 테이블이나 열은 제외합니다.
2. **관계 추가**로 관계를 직접 넣거나, 잘못된 관계를 삭제합니다.
3. **ERD 저장**을 누릅니다. 이름 중복, 잘못된 이름, 없는 열을 가리키는 관계가 있으면 "확정 전에 고칠 점"에 표시됩니다.
4. 고칠 점이 없으면 **ERD 확정**을 누릅니다. 확정한 뒤 다시 고쳐 저장하면 확정이 풀리므로 다시 확정해야 합니다.

## 스크립트 만들기

ERD를 확정하면 **스크립트** 탭에서 대상 DB(PostgreSQL, SQL Server, SQLite)를 고르고 DDL을 미리 볼 수 있습니다. **스크립트 ZIP 내려받기**를 누르면 다음 파일이 들어 있는 ZIP을 받습니다.

| 파일 | 내용 |
| --- | --- |
| `schema.sql` | 테이블·PK·FK를 만드는 DDL |
| `load.py` | 엑셀을 읽어 테이블에 넣는 Python 스크립트(부모 테이블부터 적재) |
| `mapping.json` | 시트·열과 테이블·열의 대응표 |
| `README.md` | 실행 방법 |

고객사 환경에서 `schema.sql`을 먼저 실행하고, 이어서 `load.py`를 실행합니다(DB별로 필요한 패키지와 접속 문자열 예시는 `load.py` 맨 위에 있습니다).
```powershell
pip install openpyxl psycopg
python load.py 원본.xlsx --dialect postgresql --url "postgresql://user:pw@host/db"
```

## 내보내기

상세 화면 위쪽에서 **분석 보고서(MD)**(구조·수식·경고 요약)와 **ERD(Mermaid)**를 내려받습니다. 고객사 사용자(조회 권한)는 결과를 볼 수 있지만 업로드, ERD 수정·확정, 내보내기는 할 수 없습니다.

## SpecForge로 보내기

ERD를 확정하면 ERD 탭에 **SpecForge로 보내기**가 나타납니다. 누르면 SpecForge의 새 문서 조립 화면이 열리고 이 분석의 ERD가 입력으로 선택됩니다. 확정된 ERD의 테이블·컬럼·관계는 Spec.md "도메인 개념 모델", Devin.md "데이터 모델" 섹션에 표로 들어갑니다.
