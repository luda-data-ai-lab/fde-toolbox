# OntoMap 용어 사전

고객사에서 쓰는 업무 용어를 표준 용어로 정리하고, 부서마다 다르게 부르는 호칭과 약어를 함께 관리합니다.

## 탭 구성

| 탭 | 내용 |
| --- | --- |
| 용어 사전 | 표준 용어 목록, 등록·수정, 엑셀/CSV 내보내기 |
| 개념 모델 | 개념·속성·관계 편집, 상위 온톨로지 상속 |
| 후보 | DiscoveryQ·ERD·I/F·FlowDesk·LLM에서 올라온 후보 추출과 검토 |
| 매핑 커버리지 | 개념별 매핑된 시스템 수와 미매핑 속성 |
| 검증 | 개념 모델·용어 사전의 경고 목록 |
| 엑셀 가져오기 | LUDA 용어 사전 템플릿 업로드 |

## 용어 등록

1. **용어 사전** 탭에서 **용어 등록**을 누릅니다.
2. 표준 용어, 정의, 약어, 상태(후보/확정/폐기), 비고를 입력합니다.
3. **부서별 호칭**은 `부서: 호칭; 호칭` 형식으로 적습니다. 예: `생산팀: 배합표; BOM`
4. **저장**을 누릅니다. 같은 표준 용어가 이미 있으면 등록되지 않으니 기존 용어에 병합하세요.

## 개념 모델

**개념 모델** 탭에서는 고객사 업무의 개념(예: 생산 로트, 작업지시), 개념의 속성, 개념 사이의 관계를 정리합니다.

1. 위쪽 양식에 **개념 이름**, 정의, 담당 부서, 상태(초안/확정/폐기)를 적고 **상위 개념**을 고른 뒤 **개념 등록**을 누릅니다.
   - 상위 개념은 LUDA 상위 온톨로지(예: 제조 공통 온톨로지의 "로트")나 이미 등록한 고객사 개념 중 하나입니다.
   - 상위 온톨로지는 LUDA 자산이라 모든 고객사가 같이 보지만, 여기서 만든 개념은 이 고객사에만 저장되고 자산에는 쓰이지 않습니다.
2. 목록에서 개념을 누르면 오른쪽에 상세가 열립니다. 맨 위에 상속 경로(예: `반제품 로트 → 생산 로트 → 로트 (제조 공통 온톨로지 v1)`)가 표시됩니다.
3. **속성**: 속성 이름, 데이터 형식, 단위, 필수 여부를 넣고 **속성 추가**를 누릅니다. **식별자로 지정**으로 개념을 구분하는 속성을 정합니다. 상위 개념에서 물려받은 속성은 회색으로 "상속: …"과 함께 표시됩니다.
4. **관계**: 관계 이름, 대상 개념, 카디널리티(1:1, 1:N, N:M), 역관계 이름을 넣고 **관계 추가**를 누릅니다. 상위 온톨로지에 정의된 관계도 회색으로 함께 보입니다.
5. **상위 개념 변경**과 **상태 변경**으로 바로 고칠 수 있습니다. 상속이 돌고 돌게(A → B → A) 되면 저장되지 않습니다.
6. 용어를 개념에 연결하면 상세 화면의 **연결된 용어**에 표시됩니다.

## 데이터 매핑

개념 상세의 **데이터 매핑**에서 개념·속성·관계가 실제로 어느 시스템·테이블·컬럼·I/F에 있는지 기록합니다.

1. **매핑 대상**에서 개념 자신, 속성, 관계 중 하나를 고릅니다.
2. 위치를 입력합니다. 대상마다 꼭 필요한 값이 다릅니다.
   - 개념: **시스템**(시스템 레지스트리에서 선택). 테이블은 선택입니다.
   - 속성: **컬럼**. 테이블과 시스템도 함께 적으면 좋습니다.
   - 관계: 외래키 **컬럼** 또는 **I/F**(I/F 관리에 등록된 인터페이스).
3. **테이블**·**컬럼** 칸에서는 ExMigrate에서 확정한 ERD의 테이블·컬럼을 목록으로 고를 수 있습니다. ERD 테이블을 고르면 **매핑 출처**가 ExMigrate로, I/F를 고르면 I/F로 바뀝니다. 직접 입력하면 수동입니다.
4. **매핑 추가**를 누릅니다. 필요한 값이 빠지면 저장되지 않습니다.

매핑한 속성·관계·개념을 삭제하면 그 매핑도 같이 지워집니다.

## 매핑 커버리지

**매핑 커버리지** 탭은 개념마다 매핑 수, 매핑된 시스템 수와 이름, 매핑된 속성 수/전체 속성 수, 아직 매핑되지 않은 속성을 보여줍니다. 매핑이 하나도 없는 개념은 노란색으로 표시됩니다.

## 검증

**검증** 탭은 아래 경우를 경고로 보여줍니다. 경고는 저장을 막지 않습니다.

- 상위 개념이 없는 개념
- 이름이 같은 개념
- 정의가 없는 확정 용어
- 상속한 상위 온톨로지 개념을 찾을 수 없는 경우
- 데이터 매핑이 없는 확정 개념

## 후보 검토

**후보** 탭에는 아래 출처에서 올라온 용어·개념·속성·관계 후보가 "검토 대기"로 쌓입니다. 후보는 확정하거나 병합하기 전까지 용어 사전과 개념 모델에 들어가지 않습니다. 종류·출처·상태로 목록을 거를 수 있습니다.

- **DiscoveryQ**: 워크시트에서 **용어로 등록**한 표현 → 용어 후보
- **ExMigrate ERD**(확정된 것만): 테이블 → 개념, 컬럼 → 속성("개념.속성"), 테이블 간 관계 → 관계 후보
- **I/F**: I/F 이름에서 "전송", "연동", "I/F" 같은 말을 뺀 데이터 이름 → 개념 후보(설명은 맥락으로 표시)
- **FlowDesk**: 흐름의 문서 노드 → 개념 후보(레인은 부서로 표시)
- **LLM 제안**: 아래 "LLM 제안" 결과

### 후보 추출

**후보 추출** 칸에서 **ExMigrate ERD에서 추출**, **I/F에서 추출**, **FlowDesk에서 추출**을 누르면 규칙에 따라 후보를 뽑습니다. LLM을 쓰지 않고 외부 통신도 없습니다. 같은 출처를 다시 추출해도 이미 있는 후보(확정·병합·무시한 것 포함)는 다시 만들지 않습니다.

### 확정·병합·무시

후보마다 출처와 위치(테이블·컬럼, I/F 코드, 흐름 이름), 이름이 비슷한 기존 항목이 함께 보입니다.

- **확정**
  - 용어: 새 표준 용어로 용어 사전에 추가합니다.
  - 개념: 새 개념(확정 상태)을 만듭니다. ERD에서 온 개념은 **매핑할 시스템**을 고르면 테이블 매핑도 함께 만들고, I/F에서 온 개념은 I/F 매핑을 만듭니다.
  - 속성: **소속 개념**에 속성을 추가합니다. 비워 두면 후보 이름의 개념을 찾아 씁니다. 소속 개념에 ERD 테이블 매핑이 있으면 컬럼 매핑도 만듭니다.
  - 관계: **출발 개념**과 **대상 개념** 사이에 관계를 만듭니다. 비워 두면 이름으로 찾습니다. 개념이 아직 없으면 먼저 개념 후보를 확정하세요.
  - **확정할 이름**을 입력하면 후보 이름 대신 그 이름으로 만듭니다.
- **{항목}에 병합**: 비슷한 기존 항목에 합칩니다. 용어는 부서별 호칭으로, 정의 초안은 비어 있는 정의로 들어갑니다.
- **무시**: 넣지 않습니다. **다시 열기**로 되돌릴 수 있습니다.

### LLM 제안

**LLM 제안** 칸에서 제안 종류를 고릅니다.

- **인터뷰에서 용어 추출**: 고른 DiscoveryQ 세션의 답변·인사이트에서 용어 후보를 뽑습니다.
- **개념 간 관계 제안**: 고객사 개념 목록을 보고 관계 후보를 제안합니다(개념이 2개 이상 있어야 합니다).
- **정의 초안**: 정의가 없는 용어·개념의 정의 초안을 후보로 만듭니다.

외부 연동이 꺼져 있으면 **프롬프트 만들기** → **프롬프트 복사** 후 승인된 LLM에 붙여넣고, 받은 JSON을 **LLM 응답(JSON)** 칸에 넣어 **응답으로 후보 만들기**를 누릅니다. LLM 어댑터가 승인·활성화되어 있으면 **LLM으로 제안 받기**로 바로 받습니다. 어느 쪽이든 결과는 후보 목록으로만 들어가고, 확정은 FDE가 합니다. 관계 제안 중 없는 개념을 가리키는 것은 버립니다.

## 엑셀로 가져오기

1. **엑셀 가져오기** 탭에서 LUDA 용어 사전 템플릿("용어 사전" 시트) 형식의 .xlsx 파일을 고릅니다.
2. 행마다 신규/갱신/건너뜀과 오류가 표시됩니다.
3. 반영하면 기존 용어는 갱신되고, 호칭은 기존 호칭에 추가됩니다.

## 내보내기

**엑셀 내보내기**는 다시 가져올 수 있는 템플릿 형식으로, **CSV 내보내기**는 표준 용어·정의·부서별 호칭·약어·관련 개념·비고·상태 열로 내려받습니다.
